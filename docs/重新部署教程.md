# 狐Fn主页重新部署教程

适用于本仓库：[hbxs0571/hbxs0571.github.io](https://github.com/hbxs0571/hbxs0571.github.io)

线上地址：[主页](https://home.005711.xyz/) · [关于我与留言板](https://home.005711.xyz/about.html)

本网站是静态 HTML、CSS、JavaScript 页面，托管在 GitHub Pages；留言数据单独保存在 Supabase。以后只改网页时，通常只需提交到 GitHub；继续使用现在的 Supabase 项目和域名即可保留留言并维持原地址。

## 一、重新发布网页

### 1. 修改文件

本仓库的网页入口是根目录的 index.html。常用文件如下：

| 文件 | 用途 |
| --- | --- |
| index.html | 主页文字、按钮和联系方式 |
| about.html | 关于页与留言表单 |
| asset/css/main.css、asset/css/about.css | 主页、留言页样式 |
| asset/js/main.js | 主页交互与背景轮播 |
| asset/js/guestbook.js | 留言提交和公开留言展示 |
| asset/js/guestbook-config.js | Supabase 项目 URL 和前端 publishable key |
| asset/image/ | 网站图标、微信二维码和页面图片 |

在 GitHub 仓库网页中，打开已有文件点编辑按钮；新增文件用 Add file → Create new file。确认路径和内容后，选择直接提交到 main。

### 2. 确认 GitHub Pages 发布源

1. 打开仓库 Settings → Pages。
2. 查看 Build and deployment 当前选用的发布方式。不要为了照抄教程随意切换已有的 Actions 发布方式。
3. 如果选择 Deploy from a branch，本网站文件位于仓库根目录，应选择 main 和 /(root)，然后保存。
4. 每次把网页文件提交到发布源后，打开仓库 Actions 或 Deployments，等 GitHub Pages 部署成功。
5. 部署完成后访问主页；关于页地址是 /about.html。

~~~mermaid
flowchart TD
    A[编辑或新增 HTML/CSS/JS] --> B[提交到 main]
    B --> C{Pages 发布成功?}
    C -- 是 --> D[打开主页和 about.html 检查]
    C -- 否 --> E[查看 Actions/Deployments 错误]
    E --> A
~~~

## 二、域名设置（仅在更换域名或重新绑定时需要）

仓库根目录的 CNAME 文件当前内容是 home.005711.xyz。阿里云 DNS 对应记录应为：

| 字段 | 值 |
| --- | --- |
| 记录类型 | CNAME |
| 主机记录 | home |
| 记录值 | hbxs0571.github.io |
| TTL | 使用控制台默认值即可 |

操作路径：阿里云 云解析 DNS → 005711.xyz → 添加记录，填写上表并保存。不要把 https:// 或 / 写入记录值。

然后打开 GitHub 仓库 Settings → Pages → Custom domain，填写 home.005711.xyz 并保存。等 DNS 检查通过、HTTPS 证书就绪后，再启用 Enforce HTTPS。仅在仓库中放置 CNAME 文件不会自动配置 Pages 的 Custom domain，因此这两处设置都要对应。

如果只是把当前网站内容重新提交到同一个仓库，不需要重复添加 DNS 记录，也不要删除 CNAME 文件。

## 三、配置留言数据库（仅在新建或更换 Supabase 项目时需要）

~~~mermaid
flowchart LR
    A[Supabase 项目] --> B[运行 guestbook.sql]
    B --> C[填写项目 URL 和 publishable key]
    C --> D[提交 guestbook-config.js]
    E[访客提交] --> F[待审核留言]
    F --> G{管理员批准?}
    G -- 是 --> H[公开显示]
    G -- 否 --> I[继续隐藏]
~~~

### 1. 优先沿用现有项目

如果原 Supabase 项目还在使用，继续使用原项目即可：留言表和已有留言都在数据库中，重新发布网页不会搬动或删除它们。新建的项目有独立数据库，旧项目中的留言不会自动迁移。

### 2. 新项目中创建留言表

1. 在 Supabase Dashboard 打开 SQL Editor。
2. 打开本仓库 supabase/guestbook.sql，复制全部 SQL 到编辑器并运行。
3. 在 Table Editor 确认出现 guestbook_messages 表。

SQL 会启用行级安全策略（RLS）：访客可以提交待审核留言，只能读取已批准的公开字段；邮箱不授予访客读取权限。若只是网页重新发布、数据库权限没有变化，不必重复执行 SQL。

### 3. 填写前端项目配置

1. 在 Supabase 项目 Settings → API Keys 找到 Project URL 和 publishable key。
2. 把这两项填入 asset/js/guestbook-config.js。更换 Supabase 项目时也要替换这两项。
3. 提交修改后的文件到 GitHub main，等待 Pages 发布完成。

publishable key 是设计为可放在浏览器前端的公开标识，访客能看到网页源代码中的内容；访问权限由数据库 grants 和 RLS 策略控制。不要把 Supabase secret、service_role key、数据库密码或登录凭据写进网页、教程或 GitHub 仓库。详见 [Supabase API key 文档](https://supabase.com/docs/guides/getting-started/api-keys)和 [RLS 文档](https://supabase.com/docs/guides/database/postgres/row-level-security)。

## 四、审核留言

1. 登录 Supabase Dashboard，进入 Table Editor → guestbook_messages。
2. 新留言的 approved 默认是 false，所以不会出现在网站上。
3. 阅读留言后，将要公开的那一行 approved 改成 true；页面只展示名称、留言和日期。邮箱不会由留言页公开读取。

访客页出现“这里还没有公开留言”通常表示还没有通过审核的留言；如果页面提示留言服务连接失败，再检查项目 URL、publishable key、SQL 是否已运行以及 Pages 是否已部署。

## 五、重新部署检查清单

- [ ] index.html、about.html 和 asset/ 文件位于仓库根目录下对应位置。
- [ ] GitHub Pages 部署源和 main 分支一致，最近一次 Pages 发布成功。
- [ ] CNAME 仍写着 home.005711.xyz；阿里云 home CNAME 指向 hbxs0571.github.io。
- [ ] 如果更换了 Supabase 项目，已运行 SQL 并更新 guestbook-config.js。
- [ ] 打开主页和 /about.html，确认图片、表单和留言状态正常。
- [ ] Supabase 收到新留言后，先在 Table Editor 审核，再将 approved 改为 true。
