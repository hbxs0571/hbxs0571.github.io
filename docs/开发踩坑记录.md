# 开发踩坑记录

这份文档记录在开发本网站过程中真实踩到的坑：现象、原因、怎么解决的。写在文档里的都是为了下次不再花同样的时间，不是为了记录流水账。

内容包括本机工具链的毛病、GitHub 推送失败、浏览器调试脚本的陷阱，以及前端点阵数字和爆裂动画上做过的几轮试验。

## 先认识几个词

| 名称 | 简单解释 |
| --- | --- |
| CDP | Chrome DevTools Protocol，浏览器远程调试协议；脚本可以借它开页面、点按钮、截图、读像素。 |
| 沙箱 | 运行命令时的权限限制；限制过严会让某些系统调用直接失败。 |
| 点阵数字 | 用一堆小圆点拼出数字的字形，本站主页时钟和关于页的 Token 面板都用它。 |
| 碎粒 | 数字散开时飞出去的小点，视觉上像数字炸成渣。 |
| 落点区 | 数字下方留出的空白高度，给碎粒掉落和堆积用。 |
| 墨迹 | 画布上真正有像素的区域，不含四周的透明留白。 |
| 缓存查询串 | 像 `main.css?v=20261125` 这样的版本号，改前端资源后必须同步改它。 |

## 一、本机工具链

### 1.1 PowerShell 里跑 git 会报管道错误

现象：

```text
ResourceUnavailable: 进程“git.exe”启动失败：Access to the path '\\.\pipe\LOCAL\dotnet_...' is denied.
```

原因：PowerShell 对子进程管道的处理与本机安全策略冲突，git 拿不到自己的标准输入输出管道。

解决：改用 Git Bash 执行 git 命令。本工作区的 shell 工具默认走 Git Bash，日常提交推送都正常。

### 1.2 curl 与 git 报 schannel 凭据 / 吊销检查错误

现象：

```text
curl: (35) schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS
git: cannot create standard input pipe for remote-https: Permission denied
git: schannel: next InitializeSecurityContext failed: CRYPT_E_REVOCATION_OFFLINE (0x80092013)
```

原因：前两条是沙箱限制，第三条是证书吊销列表（CRL）的在线校验连不上。

解决：克隆时临时关掉吊销检查，只对这一次命令生效：

```bash
git -c http.schannelCheckRevoke=false clone https://github.com/hbxs0571/hbxs0571.github.io.git
```

需要长期生效时写进**该仓库的本地配置**（不要动 `--global`）：

```bash
git config http.schannelcheckrevoke false
```

### 1.3 克隆超时会留下半个仓库

现象：命令超时后目录存在、`.git` 里有几 MB 数据，但文件不全，后续操作全部报错。

解决：超时后先 `rm -rf` 掉目标目录再重新克隆，不要在残留目录上继续。

### 1.4 长脚本要留意单次执行时限

现象：跑一个要开浏览器、等 5 秒落位、再采样十几帧的脚本，中途被切断。

解决：脚本单次执行默认有 120 秒上限，可以把上限调高，或者把脚本拆成两段（先落位截图，再单独分析）。

### 1.5 Node 脚本里 require 和顶层 await 不能混用

现象：

```text
ERR_AMBIGUOUS_MODULE_SYNTAX: Cannot use 'import.meta' outside a module
```

解决：把主体包进一个 async 函数再调用，不要在 `require` 旁边写顶层 `await`。

### 1.6 用模板字符串生成大段文本容易炸

现象：写入一份含大量代码块和引号的 Markdown 文档时，脚本直接报 `Expected unicode escape`。

原因：文档正文里的反引号、`\n`、引号和模板字符串自身的转义层级叠在一起，解析器先崩了。

解决：**不要用模板字符串写长文档**。改成字符串数组再拼接：

```js
const L = ["第一行", "第二行"];
await tools.write({ file_path: "docs/xxx.md", content: L.join("\n") });
```

## 二、推送到 GitHub

### 2.1 推送报 Failed to connect to github.com:443

现象：`git push` 反复失败，报 `Failed to connect to github.com:443`。

排查顺序：

| 检查 | 命令 | 说明 |
| --- | --- | --- |
| 网络通不通 | `ping github.com` | 能通说明不是整体断网 |
| 443 通不通 | `curl -s -o /dev/null -w "%{http_code}" https://github.com` | 返回 000 表示超时 |
| 端口是否被拒 | `timeout 3 bash -c "</dev/tcp/20.6.7.17/443"` | 报 Connection refused 就是被阻断 |
| 有没有本地代理 | `netstat -ano \| grep LISTENING` | 常见端口 7897 |
| 代理能不能用 | `curl -x http://127.0.0.1:7897 https://github.com` | 返回 200 就说明代理可用 |

解决：用一次性参数走代理，**不改任何 git 配置**：

```bash
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push origin main
```

### 2.2 别把「推送失败」和「推送成功」搞混

`Recv failure: Connection was reset` 这类报错有时出现在服务端已经收下提交之后。判断真实状态的唯一办法是问远端：

```bash
git ls-remote origin main
```

输出里的 SHA 与本地 `git rev-parse HEAD` 一致，就是真的推上去了；不一致再重推。

## 三、浏览器调试脚本（CDP）

### 3.1 新建标签页不能用 GET

现象：`/json/new?url=...` 返回一段纯文本 `Using unsafe HTTP verb GET to invoke /json/new.`，`JSON.parse` 直接抛错。

解决：改用 `PUT`，或者干脆复用已有标签页：

```js
const list = await (await fetch('http://127.0.0.1:9333/json/list')).json();
const page = list.find(t => t.type === 'page');
const ws = new WebSocket(page.webSocketDebuggerUrl);
```

### 3.2 导航后立刻取值，拿到的是旧页面

现象：`Page.navigate` 之后马上读画布，得到默认的 300x150 空白画布，所有测量值都是 0。

解决：轮询等页面真正就绪，**并且带上业务特征判据**。只等 `readyState` 不够，因为脚本还在下载；要等到画布真的被业务代码初始化：

```js
for (let i = 0; i < 40; i++) {
  const ok = await ev("document.readyState==='complete' && (function(){var c=document.querySelector('#token-canvas');return c && c.width>100;})()");
  if (ok) break;
  await new Promise(r => setTimeout(r, 200));
}
```

### 3.3 截图裁剪用的是文档坐标

现象：想截某个卡片，传进去 `getBoundingClientRect()` 的 `top`，截出来却是页头。

原因：`Page.captureScreenshot` 的 `clip` 用的是文档坐标，`getBoundingClientRect()` 给的是视口坐标。

解决：加 `window.scrollY`（水平方向加 `window.scrollX`）：

```js
const r = el.getBoundingClientRect();
const clip = { x: r.left, y: r.top + window.scrollY, width: r.width, height: r.height, scale: 2 };
```

### 3.4 必须关掉缓存，否则量到旧样式

现象：改了 CSS 里的 padding，脚本量出来还是旧值；改了 JS，行为没变。

原因：调试脚本复用同一个浏览器实例，静态资源命中磁盘缓存，而 HTML 里的 `?v=` 没改就不会重新拉取。

解决：每个测量脚本开头都关缓存：

```js
await send('Network.enable');
await send('Network.setCacheDisabled', { cacheDisabled: true });
```

### 3.5 截图缩放因子必须设 1

现象：脚本截出来的图很清晰，但用户屏幕上看是糊的。

原因：`deviceScaleFactor` 默认跟随设备，截到的是 2 倍图，把每个点放大后看起来都独立；用户实际看的是 1 倍像素，点会互相啃。

解决：评估「用户看到的效果」时固定 `deviceScaleFactor: 1, scale: 1`。要看细节再单独放大截图。

### 3.6 基准图和采样图必须用同一个阈值

现象：动画结束后判定「还有残留」，但肉眼看不出来。

原因：基准掩膜用 `alpha > 40`，采样用 `alpha > 20`，把一千多个抗锯齿边缘像素算成了残留。

解决：基准和采样用同一个 alpha 阈值，两边都写死成同一个常量。

### 3.7 抓动画帧时采集器不能抢跑

现象：抓了 9 帧，9 张图 sha256 完全一样。

原因：采集用的 `requestAnimationFrame` 循环在点击**之前**就启动了，等点击发生时配额已经用完，抓到的全是点击前的静止画面。

解决：把「启动采集」和「触发点击」写在**同一句**里执行，并让采集器按时间槽（60/140/240/360…ms）而不是按帧数分配：

```js
await ev("window.__startRec(); document.querySelector('.token-counter').click();");
```

### 3.8 分析像素要用画布直出，不要用页面截图

现象：对页面截图做背景估计，掩膜覆盖整张图，完全没法分析。

原因：页面截图里有壁纸，颜色随机、亮暗都有，没有可靠的背景色。

解决：用 `canvas.toDataURL('image/png')` 拿纯画布像素，背景是透明的，`alpha` 通道直接就是掩膜。

## 四、点阵数字渲染

### 4.1 十几个字符的点阵糊成一条色带

现象：完整数字 `13,297,431,000` 有 14 个字符，画出来整行糊在一起，认不出字符。

原因：点距按 `2r` 排（点与点正好相切），再叠一圈 `0.22r` 的深色描边，相邻点就粘住了；字符一多、半径被压到 3.7px 左右，粘连后直接变成实心条。

解决：在点距里留出间隙。改完宽度公式要记得减掉一项修正，否则右边比左边宽。

```js
var DOT_GAP = 0.7;   // 相邻点的间隙，单位是半径（最终改回 0，见本节末尾）
// 每个字形最后一列后面不需要点间隙，多算的总量恒等于一个 DOT_GAP·r，
// 与字符数无关，所以统一减掉一次。
function solveRadius(glyphs, targetW, gapRatio) {
  var cols = glyphCols(glyphs);
  var gaps = Math.max(0, glyphs.length - 1);
  return targetW / (cols * (2 + DOT_GAP) + gaps * gapRatio - DOT_GAP);
}
```

试过的五个方案（固定 944px 宽、1 倍像素渲染后目视对比）：

| 方案 | 点间隙 | 描边 | 半径 | 结论 |
| --- | --- | --- | --- | --- |
| A | 0 | 0.22r | 4.79 | 糊成色带 |
| B | 0.35r | 0.22r | 4.17 | 仍然粘连 |
| C | 0.35r | 无 | 4.17 | 略好 |
| **D** | **0.7r** | **0.22r** | **3.70** | **每点独立可见，最清楚** |
| E | 0.7r | 无 | 4.17 | 稍弱 |

结论：**留间隙比去描边有效得多**。描边是给「点压在亮壁纸上」用的，不能删，该让位的是点距。

**后来这个结论被推翻了。** 上面那轮实验的前提是「彩虹配色 + 保留描边」，在这个前提下点必须留缝才分得开。但主页时钟根本没有彩虹配色，也没有描边 —— 它是整幅单色、点严格相切。照抄主页之后 `DOT_GAP` 又改回了 `0`，因为单色相切的点读起来是「实心块面数字」，留缝反而让字形变成稀疏点阵。真正的教训是：**配色和点距是一套语言，不能拆开单独调**。

### 4.2 点阵数字的四边边距不相等

现象：左边距 18px，右边距 16px，差 2px。

原因：画布 CSS 宽是 `width + INK_PAD * 2`，如果直接把容器的 `clientWidth` 当目标宽度，画布就比容器宽 2px，被 `max-width: 100%` 压回去，内部绘制被横向压缩，右边就少 2px。

解决：目标宽度先扣掉左右两份内边距：

```js
var targetW = Math.max(1, cw - INK_PAD * 2);
```

顺便说一句：主页时钟本身的四边其实**并不等距**（实测左 26.5、右 1.5、上 12.7、下 0），只是画布小看不出来。所以「和主页时钟一样」这个目标本身是矛盾的，这块要的是真正的等距。

### 4.3 单位角标会占位，把数字挤窄

现象：`tokens` 角标要么跑到垂直中间，要么占掉一段宽度挤压数字。

原因：角标参与了 flex 布局，`align-items` 怎么调都还在文档流里。

解决：让角标彻底脱离布局，只做视觉浮层，JS 里也不再考虑它的宽度：

```css
.token-figure { position: relative; display: block; }
.token-unit   { position: absolute; right: 0; bottom: 0; pointer-events: none; }
```

角标会和数字最后一个字符轻微重叠，这是刻意的，重叠可接受。

### 4.4 热力图月份标签被裁成半个字

现象：最左边标签显示成「1月」，其实是「11月」被裁掉了。

原因：一年最少 53 周，首尾月份常常只剩一两列宽，文字塞不下就被裁。

解决：跨度不足 2 列就干脆不画；年份很占宽，只在跨度够 4 列时才加。GitHub 本身也是这么处理的。

```js
var span = (k + 1 < marks.length ? marks[k + 1].w : weeks) - mk.w;
if (span < 2) continue;
var text = (mk.m + 1) + "月";
if ((firstDrawn || mk.m === 0) && span >= 4) text = mk.y + "年" + text;
```

## 五、爆裂动画

### 5.1 主页时钟是怎么做的

主页时钟（`asset/js/clock.js`）的规则，逐条记下来当参照：

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 画布尺寸 | 820 x 250 | 数字只占 y=30..170 |
| 点半径 | 7 | 点距正好 2r，相切 |
| 步进 | `setInterval(..., 50)` | 50ms 一步，位移就是 vx / vy 原值 |
| 初速 | vx 随机 ±(4~5)、vy -5 | 向上飞一点点就落 |
| 重力 | 1.5 + random | 每步累加 |
| 落地反弹 | `vy = -vy * 0.65` | 落在 `画布高 - r` |
| 回收 | 只看 x 出界 | 不按时间回收 |
| 触发 | 数字变化的那一位 | 不是全字爆 |

关键点：**画布 250 高，数字底在 170，下面空出 80px 专门给碎粒掉落**。

### 5.2 关于页照搬之后数字糊成一团

现象：点击展开时碎粒在底部堆成一条彩带，数字完全认不出。

原因有四层，从重到轻：

1. **画布只有 99px 高，数字几乎占满全高**，碎粒出生就贴地，没有下落空间，只能横向铺开；回收条件只看 x，碎粒永远出不去，越堆越满。
2. 物理跑在 rAF（约 16.7ms/帧）但参数照抄 50ms 步进的值，速度变 3 倍、重力变 9 倍。
3. 碎粒和数字同尺寸同色，还画在数字下层，把点与点之间的空隙填满，字形看着变粗变糊。
4. 点击时 800 多个点**同时**炸，而主页时钟一次只炸一位（几十颗），密度完全不是一个量级。

解决办法，逐条对应：

**① 借 padding 当落点区。** 玻璃板本身有 padding，画布向下延伸借用它，再用负 margin 抵消布局影响，玻璃板高度和四边等距都不变。

```js
var padBottom = 0;
var clockEl = canvas.closest(".token-clock");
if (clockEl) padBottom = parseFloat(window.getComputedStyle(clockEl).paddingBottom) || 0;
var cssH = height + INK_PAD * 2 + padBottom;
canvas.style.height = cssH + "px";
canvas.style.marginBottom = -padBottom + "px";
```

前提是 `.token-clock` 和 `.token-figure` 都不能有 `overflow: hidden`，否则延伸部分会被裁掉。

**② 物理按时间缩放。** 以 50ms 为一个时间单位，按真实帧间隔缩放，上限 3 个单位避免切后台回来一帧跳出去。

```js
var dt = Math.min((now - lastT) / CLOCK_TICK, 3);
b.x += b.vx * dt;
b.y += b.vy * dt;
b.vy += b.g * dt;
```

**③ 碎粒缩小、变淡、只抽一部分。** 三个参数一起调，缺一个效果都不对：

| 参数 | 取值 | 作用 |
| --- | --- | --- |
| `DEBRIS_SCALE` | 0.62 | 碎粒比数字点小一号，读作「渣」 |
| `DEBRIS_ALPHA` | 0.9 | 出生时略透明 |
| `DEBRIS_RATIO` | 0.28 | 只抽 28% 的点生碎粒，留出空隙 |

实测数字区域被遮挡的比例（碎粒像素 / 数字像素），改前改后对比：

| 时刻 | 改前 | 加缩放+淡 | 再加抽稀 |
| --- | --- | --- | --- |
| 140ms | 0.644 | 0.258 | **0.085** |
| 360ms | 0.516 | 0.275 | **0.082** |
| 700ms | 0.320 | 0.147 | **0.039** |

**④ 碎粒要画在数字下面，并且循环结束必须恢复 `globalAlpha`**，否则数字本体也跟着变半透明。

上面 ③ 的这组参数是中间产物，最终没有采用（缩碎粒、抽稀都是在「点阵语言已经错了」的前提下打补丁）。真正解决问题的办法见 5.6。

### 5.3 长尾问题：为什么用淡出而不是照搬物理

主页时钟每秒重置一次，碎粒的长尾被下一次重置吃掉，人眼只看到「炸开 → 落下 → 滚走一小段」。

关于页没有下一次重置。如果照搬物理，实测归零要 **3836ms**：画布 942 宽，碎粒横向速度 4~5px/帧，最边缘那颗要走完约 932px，`(942 + 3 - 10) / 4 ≈ 233 帧 ≈ 3.9s`。

这不是还原，是放大 —— 把本该看不见的尾巴完整暴露出来。所以**物理参数一个不动**，用淡出代替「被吃掉」的那一刻：

```js
var DEBRIS_FADE_START = 1100;
var DEBRIS_END = 1700;
```

否决的方案：把 vx 提到 11~13 让长尾缩短到 2.3 倍速 —— 视觉会从「滚走」变成「射出去」，不是同一个动作。

（最终取值为 `DEBRIS_FADE_START = 500`、`DEBRIS_END = 900`，配合逐位爆裂，见 5.6。）

### 5.4 数字横向抖动一直不收敛

现象：数字落位后每个点永久偏在目标位旁边，字形被抖散。

原因：粒子初始位置在 x 方向有 ±18px 随机抖动，但回收循环只把 y 往目标位收敛，x 从来没管过。

解决：x 也按同样方式收敛，并加一道兜底强制归位：

```js
p.cx += (p.tx - p.cx) * 0.18;
// 帧数到上限还没收敛就直接归位，否则永久停在半空，数字一直是糊的
if (frames >= 320) snapAll();
```

### 5.5 照抄主页时钟的点阵语言（最终方案）

前面 5.2 的修法（缩碎粒、抽稀、缩画布）都只是让「糊」变轻，没解决根本问题：字形语言本身就不一样。用户反复说的是「照抄主页时钟」，逐条拆开对比之后才找到真正的四个差异。

| 维度 | 关于页原来 | 主页时钟 | 最终 |
| --- | --- | --- | --- |
| 配色 | 横向彩虹渐变，每个点不同色 | 整幅单色，每秒推进一个色号，15 色一轮 | 照抄主页 |
| 点距 | `DOT_GAP = 0.7`（留缝） | 严格 2r，相切 | `DOT_GAP = 0` |
| 描边 | 每点 0.22r 深色描边 | 无描边，只 fill | 删除 |
| 触发 | 一次全炸 800+ 颗 | 只炸变化的那一位，约 30 颗 | 从左到右逐位，`STAGGER = 150` |

**最关键的一条是配色。** 主页时钟 `asset/js/clock.js` 里整幅数字同一时刻只有一个颜色：

```js
var currentSecond = r.getSeconds();
if (currentSecond !== lastSecond) {
  currentColorIndex = (currentColorIndex + 1) % v.length;
  lastSecond = currentSecond;
}
f.fillStyle = v[currentColorIndex];
```

关于页原来那套「横向彩虹渐变」在主页时钟里根本不存在 —— 那是自己加的。彩虹配色下每个点都是独立色块，字形读作「彩色碎屑拼的」；改成单色之后，相切的点立刻读作「实心块面数字」。**单色是这套动画能「炸得开又看得清」的前提。**

逐位爆裂的实现要点：

```js
// 每 STAGGER 毫秒解锁下一位，从左到右
var due = Math.floor((now - t0) / STAGGER) + 1;
while (nextGlyph < currentGlyphCount && nextGlyph < due) {
  spawnDebrisForGlyph(nextGlyph, radius);
  nextGlyph++;
}
```

逐位本身就解决了密度问题 —— 同一时刻只有一两位在掉渣，其余位静止，字形轮廓始终在。所以碎粒尺寸可以恢复原大（`DEBRIS_SCALE = 1`）、透明度恢复（`DEBRIS_ALPHA = 1`），只需要 `DEBRIS_RATIO = 0.4` 再抽掉一部分，避免 14 位同时在飞时填满空隙。

**实测遮挡率对比（1440 宽，worst）**：

| 版本 | worst 遮挡率 |
| --- | --- |
| 全量同时炸 + 200-400ms 淡出 | 0.349 |
| ratio 0.25 + stagger 80 | 0.109 |
| ratio 0.35 + 450-750ms 淡出 | 0.114 |
| **ratio 0.40 + stagger 150 + 500-900ms 淡出** | **0.084** |

390 窄屏 worst 0.135（t400 峰值，t1000 起归零）。

**画布加高 56px 那版被否掉了。** 实测遮挡率能降到 0.075，但碎粒会落到玻璃板外面的壁纸上（`.token-clock` 没有 `overflow: hidden`），和主页「落在画布内底边」不一致；而且实拍显示画布下方多出一条空带、数字被顶到上沿，四边等距的观感被破坏。**宁可用密度换，不用画布尺寸换。**

### 5.6 爆裂验收清单

改完动画至少跑这几项，任何一项不通过都不算完成：

| 场景 | 判据 |
| --- | --- |
| 桌面 1440 展开 | 碎粒最大 y 明显超过数字底行，且 3s 内归零 |
| 桌面 1440 收起 | 同样能归零，不残留 |
| 390 窄屏 | 无横向溢出，碎粒仍落在数字下方 |
| `prefers-reduced-motion: reduce` | 完全不产生碎粒，像素数全程不变 |
| 连续点击 3 次 | 峰值不累积（与单次同量级），最终归零，无 JS 报错 |
| 动画结束后 | `alpha > 40` 掩膜与爆裂前逐像素相等（`diff px = 0`） |

实测参考值（1440 宽）：落位后墨迹 29712 像素，爆裂峰值 32855，**2750ms 完全回到 29712** 并保持到 4500ms。归零时间由「最后一位出生时刻 + 淡出窗口」决定：`150 × 13 + 900 ≈ 2850ms`。

**归零判据不能只看淡出窗口。** 逐位爆裂下最后一位要到 1950ms 才出生，如果按「1.8s 内归零」验收会一直失败。

**掩膜比对必须同阈值。** 基线帧和采样帧都用 `alpha > 40`，混用 `alpha > 40` 与 `alpha > 20` 会把上千个抗锯齿边缘像素误判成残留。
